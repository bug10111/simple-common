# 需求分析与开发计划技能（Requirement Planner）

## 触发条件

用户下达编码任务、功能开发请求时，**优先调用本技能**进行需求理解与计划制定，再进入编码阶段。

---

## 工作流程（严格按序执行，不可跳过）

### 第一步：需求分析

1. **明确用户目标**
   - 提炼核心需求，一句话概括要做什么。
   - 判断涉及技术栈：
     - 仅 Java（后端接口/服务/定时任务）
     - 仅 Web（前端页面/组件）
     - Java + Web（全栈）

2. **识别涉及模块**
   - 列出需要新增/修改的模块范围：
     - Controller / Service / View / Repository / Mapper XML / Entity / DTO / Enum / Config
   - 初步标注每个模块的改动类型（新增/修改/不变）。

---

### 第二步：绘制简易符号流程图

使用 ASCII 字符快速勾勒业务处理的主干步骤、关键判断节点及数据流向。

**符号约定**：
```
→  数据流向 / 下一步
↓  下行流转
□  处理步骤
◇  判断节点
[] 数据/对象
```

**示例**：
```
请求进入
  ↓
□ 参数校验 (Controller)
  ↓
◇ 数据是否存在？
  ├── 是 → □ 更新数据 → [更新结果]
  └── 否 → □ 新增数据 → [新增结果]
  ↓
□ 返回响应
```

**要求**：
- 流程图必须反映对业务逻辑的**整体理解**。
- 标注关键判断节点和分支走向。
- 标注数据对象在各阶段的形态。

---

### 第三步：第一次反省自检（基于代码，禁止猜想）

**这是最关键的一步，必须基于实际源代码验证。**

#### 3.1 全面阅读相关模块代码

对每个涉及模块，按以下顺序逐一 `read_file`：

```
Controller 类
  → Service 接口 + Service 实现
    → View 接口 + View 实现
      → Repository 接口
        → Mapper XML
```

涉及 Entity、DTO、Enum 等辅助类也必须阅读。

#### 3.2 对照流程图逐节点核对

- 每个流程节点是否有对应的代码支撑？
- 现有代码逻辑是否与流程图一致？
- 需要**新增**什么？（类、方法、字段、SQL）
- 需要**修改**什么？（改逻辑、加参数、改 SQL）
- 哪些**不变**？（复用现有代码）

#### 3.3 中断条件

以下情况**必须立即中断**，向用户描述现状并等待回复：

- 关键源码文件找不到
- 现有代码逻辑与需求矛盾且无法自行判断
- 缺少必要的配置信息（数据库表结构、第三方接口文档等）
- 依赖的外部服务/模块代码不在当前项目

**中断输出格式**：
```
已探明部分：
- xxx 模块：已有 xxxController、xxxService，逻辑为 xxx
- xxx 模块：未找到对应代码

缺失信息：
1. 需要 xxx 的表结构定义
2. 需要 xxx 接口的文档
3. ...

请提供以上信息后继续。
```

#### 3.4 确认后可继续

只有满足以下条件才进入下一步：
- 流程正确
- 与现有业务契合
- 改动点清晰明确

---

### 第四步：按需加载规范文件

根据技术栈选择性加载：

| 技术栈 | 需加载规范 |
|--------|-----------|
| Java | `java代码编辑规范.md` |
| Web | `web代码编辑规范.md` |
| Java + Web | 两者都加载 |

加载后简要注明本次任务重点关注哪些规范条目。

---

### 第五步：输出开发计划

每行一个步骤，以 `- ` 开头。

**格式**：
```
开发计划：
- 步骤1: 创建 xxxRequest DTO（PageXxxRequest），字段包括 xxx
- 步骤2: 创建 xxxResponse DTO（PageXxxResponse），字段包括 xxx
- 步骤3: 在 XxxView 接口新增 findAll 方法
- 步骤4: 在 MPXxxView 实现 findAll 方法
- 步骤5: 在 XxxRepository 新增 selectPage 方法
- 步骤6: 在 mapper/XxxDao.xml 编写分页 SQL
- 步骤7: 在 XxxService 接口新增 findAll 方法
- 步骤8: 在 DefaultXxxService 实现 findAll 方法
- 步骤9: 在 XxxController 新增分页查询接口
- 步骤10: 编译验证：mvn clean compile
```

**计划要求**：
- 步骤粒度适中，每步一个可独立完成的操作。
- 按依赖关系排序（先 DTO → 再 View → 再 Repository → 再 Service → 再 Controller）。
- 超过 5 步时，将计划写入 `doc/dev-plan/{功能名称}.md` 文件（该文件仅作参考，不算正式文档）。
- 标注关键文件路径。

---

### 第六步：计划写入 md 文件（超过 5 步时）

**文件路径**：`{项目根目录}/doc/dev-plan/{功能名称}.md`

**内容包含**：
- 开发计划步骤列表
- 重点业务流程说明
- 重要文件索引表

**文件索引表格式**：
```
| 文件 | 路径 | 改动类型 | 说明 |
|------|------|---------|------|
| XxxController | src/.../XxxController.java | 修改 | 新增分页查询接口 |
| XxxDao.xml | src/.../mapper/XxxDao.xml | 修改 | 新增分页 SQL |
```

## 铁律

1. **基于代码，禁止猜想**：所有验证必须通过 `read_file` 实际阅读源码。
2. **找不到必中断**：关键信息缺失时立即停止，列出需要用户提供的内容。
3. **流程必须对**：只有流程图与代码一致、改动点清晰后才可输出计划。
4. **计划可执行**：每步独立、有序、可编译验证。
5. **引用真实文件**：计划中的文件路径必须与实际项目结构一致。
